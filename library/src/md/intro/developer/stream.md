# Stream-соединения

В T-Invest API реализовано несколько Stream-соединений:

- [Стрим заявок](/invest/services/orders/orders_state_stream) — для получения состояний выставленных заявок.

- [Стрим исполнения поручений пользователя](/invest/services/orders/head-orders/#stream) — для получения всех совершенных сделок.

- [Bidirectional-стрим получения биржевой информации](/invest/services/quotes/head-marketdata/#bidirectional-stream) — биржевая информация о стаканах, свечах и другие данные.

- [Server-side стрим](/invest/services/quotes/marketdata/#marketdatastreamservice) — соединение для трансляции биржевой информации клиентам, которые не поддерживают bidirectional-стримы.

- [Стрим позиций](/invest/services/operations/methods#positionsstream) — Server-side соединение обновлений информации по изменению позиций портфеля.

- [Стрим портфеля](/invest/services/operations/methods#portfoliostream) — Server-side соединение обновлений портфеля.

- [Стрим операций](/invest/services/operations/operations_stream) — соединение для получения операций.

## Ping

Во всех Stream-соединениях реализована проверка активности стрима. При использовании сервисов T-Invest API рекомендуем добавлять проверки на получение пинга.

### Значения Ping-responce сообщений для стримов

Для всех стрим-соединений по умолчанию интервал между пингом — 120 секунд. При этом возможно задать интервал в диапазоне от 5 секунд до 180 секунд, используя
соответствующие параметры при открытии стрима.

Ping сообщения приходят только при отсутствии в стриме других сообщений.

## WebSocket

Для получения стриминговых сообщений через WebSocket реализован отдельный сервис — у него своя лимитная политика.


## Разрывы Stream-соединений

### Причины разрывов стрим-соединений

Разрыв стрим-соединения — ситуация, которая может возникнуть при работе с
потоковым данными. Причины разрывов могут быть разные, вот некоторые из них:

- Ограничения API (например, при отсутствии подписок).
- Проблемы с сетью (нестабильное интернет соединение, потеря пакетов, файрволы и др.).
- Перегрузка клиента (клиент не успевает обрабатывать данные).
- Ошибки в коде или логике приложения (утечки памяти в стрим-обработчике, некорректная обработка ошибок, отсутствие retry-логики).
- Технические работы брокера или провайдера (обновления, профилактика, сбои).


### Что делать при разрыве стрима?

- Подписывайтесь на события завершения и ошибки.

- Реализуйте retry-механизм переподключения с экспоненциальной задержкой (например, 1, 10, 60 сек).
  Не пытайтесь переподключаться слишком часто — это может усугубить ситуацию.

- Восстанавливайте данные, после переподключения. За время разрыва можно потерять данные, например: исполненные поручения, пропущенные котировки, состояния заявок.
  Используйте unary методы для получения данных, которые были потеряны в стриме.


### Рекомендации по устойчивой реализации

- Используйте асинхронные взаимодействия для масштабирования и исключения блокировок.
- Разделяйте стримы при большом количестве инструментов.
- При отсутствии данных в стриме переподключайтесь, даже если нет ошибок.
- Не держите стрим ради "фона". Если вам не нужны данные — отписывайтесь. Это снижает нагрузку и риск разрыва.
- Используйте health-check. Периодически проверяйте доступность API через `ping` или `GetMySubscriptions`.
